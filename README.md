# KK语音合成 (ldmpl_kktts)

基于 kktts API（`https://api-v2.yuafeng.cn/API/kktts.php`）的 AstrBot / ldmbot 语音合成插件。

## 功能

- **指令合成语音**：`tts <文本>` 用当前会话音色把任意文本转成语音发送
- **LLM 生成后合成**：`tts生成 <提示词>` 调用当前 LLM 生成口播文案再转语音
- **指定音色角色**：按名称或 ID 切换音色，按会话记忆（群/私聊各自独立）
- **概率自动转语音**：LLM 的回复按概率自动转成语音发送（可配置发送前替换成语音或额外追加一条）
- **失败回退文字**：任何合成失败场景下，原文字正常发送，不影响对话
- **LLM 工具（Function-calling）**：LLM 可主动调用 `kktts_speak` 开口说话、`kktts_search_voice` 查询音色

## 指令

主指令为指令组 `tts`（别名：语音合成、说），子指令用空格分隔，也可连写：

| 指令 | 说明 |
| --- | --- |
| `tts <文本>` | 合成文本为语音（= `tts say <文本>`） |
| `tts help` | 显示全部指令帮助（= `tts 帮助`，连写 `tts帮助`） |
| `tts 角色 [名称/ID/随机/重置]` | 查看/设置会话音色（连写 `tts角色`，别名：语音角色、tts音色） |
| `tts 列表 [关键词] [页码]` | 搜索音色列表（连写 `tts列表`，别名：音色列表） |
| `tts 生成 <提示词>` | LLM 生成文案并合成语音（连写 `tts生成`，别名：tts说） |
| `tts 自动 [0-100/开/关/重置]` | 会话级自动转语音概率（连写 `tts自动`，别名：自动语音） |
| `tts 状态` | 查看当前设置（连写 `tts状态`） |
| `tts 刷新` | 强制刷新音色列表缓存（连写 `tts刷新`） |

只输入 `/tts` 会列出指令树；`/tts 帮助` 是整理好的中文帮助。所有指令均需带机器人唤醒前缀（默认 `/`）。

## LLM 工具

插件注册了两个 Function-calling 工具，LLM 在对话中可自主决定调用（例如用户说「用萝莉音说一句晚安」时，LLM 会先查音色再开口）：

- `kktts_speak(text, voice?)`：让 LLM 直接把一段文本合成语音发到聊天；`voice` 留空用会话当前音色。发送成功后借用冷却窗口抑制概率自动转语音，避免同一句话连发两条语音；失败时返回错误信息，LLM 会改用纯文字回复（回退）。
- `kktts_search_voice(keyword)`：按关键词模糊搜索音色（名称/分类/ID），返回名称与完整 ID 供 `kktts_speak` 使用。

## 配置项（WebUI 插件配置）

- `api_base`：TTS 接口地址
- `default_voice_id` / `default_voice_name`：默认音色（默认「甜妹音」，已实测可用）
- `auto_tts`：LLM 回复自动转语音总开关（默认开）
- `auto_probability`：全局自动转语音概率（默认 10%）
- `auto_mode`：`替换文本`（发送前把该条回复换成语音，仅非流式平台）/ `附加语音`（文字照发，语音追加）
- `min_text_length` / `max_text_length`：自动转换的文本长度窗口（默认 2~300 字）
- `cooldown`：同会话自动语音冷却秒数（默认 30 秒）
- `tts_timeout`：合成请求超时（默认 60 秒）
- `cache_hours`：音色列表缓存时长（默认 24 小时）
- `llm_system_prompt`：`tts生成` 指令使用的 LLM 系统提示词

## 自动转语音说明

两种模式挂在不同钩子上，区别是「什么时候动这条消息」：

- **替换文本**（默认）：在 `on_decorating_result`（发送前钩子）把出站消息链换成语音组件。此时 LLMResponse 已经没有别的消费者要读，`completion_text` / `result_chain` 保持完整——历史落库、群聊上下文持久化拿到的都是纯文本原文，语音组件不会进上下文。
- **附加语音**：在 `on_llm_response` 里按概率合成，文字照常发送，语音额外追发一条。

平台差异：替换文本**只支持非流式平台**（QQ / aiocqhttp）。流式平台（WebChat 等）文字在响应过程中已先行流出、无法撤回，替换模式对流式结果直接跳过（不转语音），需要语音请改用**附加语音**。指令、错误等非 LLM 结果也不会被替换。

> 为什么要放在发送前：`completion_text` 是 `result_chain` 的派生属性（链里没有 Plain 就读成空串）。旧版本在 `on_llm_response` 里直接把 `result_chain` 换成纯语音链，会让同一钩子之后的消费者（历史落库、群聊消息持久化）看到「正文已被删空的回复」，该轮对话连同用户消息一起不进历史，表现为下一轮失忆。现已改为发送前替换，不再触碰 `LLMResponse`。

合成失败时不会改动任何结果，文字回复照常送达，即天然回退。每个会话可以用 `tts自动` 单独覆盖全局概率；`tts自动 关` 完全关闭本会话的自动语音（手动指令不受影响）。

## 数据目录

`data/plugin_data/ldmpl_kktts/`

- `voices.json`：音色列表缓存
- `sessions.json`：各会话的音色/概率设置
- `audio_cache/`：临时音频缓存（1 小时后自动清理，插件卸载时清空）
